# 財產盤點 App 功能清單

> **用途**：整理 App 現行版本**實際具備**的功能（逐項對照程式碼確認，含畫面上看不到的可靠性設計），並附上一份「還沒有的功能」提問，幫助提出需求的使用者聯想出尚未提到、但實際盤點可能需要的需求。
>
> 看的時候，建議一邊確認「現有功能夠不夠用」（當驗收基準），一邊留意下半部的缺口提問（當腦力激盪清單）。

**使用流程總覽：** 選擇模式 → 載入 CSV → 掃碼盤點 → 結果寫回 CSV → 回傳電腦

---

## 一、目前已具備的功能

依使用流程分類。每一項都是現行版本已經能用的功能。

### 🗂️ 開始盤點（模式選擇）

- 開啟 App 先選擇作業模式：**全盤（自盤）** 或 **抽盤**

### 🔁 資料匯入 / 匯出（與電腦交換）

- 從手機檔案選擇器**載入**電腦提供的 CSV 財產清單
- 盤點結果自動**寫回同一個 CSV**，再回傳電腦
- 相容 ERP 報表的中文編碼（Big5），不會亂碼
- 記住檔案位置，App 關掉重開仍可讀寫同一份
- 掃描當下先存記憶體、離開畫面才寫檔，**降低寫壞檔風險**（序列化先行、定點寫檔）

### 📋 全盤清單畫面（自盤）

- 顯示總盤點**進度**（已盤 / 全部）
- 四個分頁即時計數：**全部 / 未盤點 / 已盤點 / 不相符**
- 每筆卡片顯示：財產編號、名稱、部門、地點、盤點時間、狀態
- 切換分頁檢視各狀態；無資料時顯示提示文字

### 📷 全盤掃描

- 即時相機掃 QR Code，可開**手電筒**補光
- 自動判定四種結果：相符、不相符、未列入清單、誤觸忽略
- **誤觸過濾**：自動擋掉掃到的無關條碼 / URL（依編號格式判斷）
- 防手震：同一張碼短時間內不重複記錄（掃描冷卻 + 去重）
- 掃到清單外財產可**當場新增**（盤盈）
- 上一筆 / 下一筆回看本次盤過的財產
- 結果即時提示（成功 / 不相符 / 未列入）

### 🎯 抽盤作業

- 載入抽盤清單，**逐筆**進行（第 N 筆 / 共 M 筆）
- 上一筆 / 下一筆瀏覽
- 一鍵**跳到下一筆（或上一筆）還沒盤的**財產
- 顯示目標財產與狀態：待掃描 / 相符 / 不相符
- 顯示抽盤進度（已盤 / 共）

### 🔎 抽盤掃描

- 指定「要找的那一筆」來掃，畫面顯示正在尋找的編號與名稱
- **只認目標財產**；掃到別的會提示「不是要找的」
- 掃到正確財產會**震動**提示
- 可開手電筒、可取消

### ⚙️ 共通 / 系統

- 首次使用時請求相機權限，未授權會提示
- 自動處理瀏海 / 狀態列，畫面不被遮擋

## 二、可以想想看：目前「還沒有」的功能

以下不是缺點，而是**常見的下一步**。逐條看，問自己「我們的實際盤點會不會需要？」——需要的，就寫進規格需求裡。

> **用法提示：** 看到有感覺的先打個勾；每一個勾，都可以套用「需求撰寫指南」的八個區塊，展開成一條正式需求。

### 🔍 找東西 / 篩選

- **現況：** 清單只能上下滑 + 依狀態分頁，沒有關鍵字搜尋。
  - *想想看：* 清單一多（上百筆）時，要盤特定某一筆會不會很難找？需不需要用編號 / 名稱搜尋？
- **現況：** 只能依「盤點狀態」篩選，不能依部門或地點。
  - *想想看：* 會不會想「只盤某個部門」或「只盤某一層樓 / 某個庫房」？

### 📝 記錄更多資訊

- **現況：** 不相符時只記一個標記，無法填原因、加備註或拍照。
  - *想想看：* 現場發現對不上時，需不需要記「為什麼」或拍照存證？
- **現況：** 掃到財產後，修改其部門 / 地點的功能目前未開放。
  - *想想看：* 現場發現清單資料有誤，要能當場更正嗎？
- **現況：** 清單只有四個欄位（編號 / 名稱 / 部門 / 地點），也沒有記錄盤點人。
  - *想想看：* 需不需要照片、廠牌、金額、取得日期？需不需要記「誰盤的」做稽核？

### 📊 盤點結果 / 報表

- **現況：** 結果只寫回 CSV，App 內沒有盤點總結畫面。
  - *想想看：* 要不要在手機上直接看盤點結果（相符率、盤盈、盤虧數）？
- **現況：** 盤到最後仍未盤點的（漏盤），只能自己看「未盤點」分頁。
  - *想想看：* 要不要一鍵列出 / 匯出「漏盤清單」交差？

### 🛟 備援 / 例外狀況

- **現況：** 只能用掃的，沒有手動輸入編號的備援。
  - *想想看：* 如果 QR 貼紙破損 / 掉了，要能手動輸入編號補盤嗎？
- **現況：** 目前針對 QR Code；全盤掃到只跳畫面提示（抽盤才有震動）。
  - *想想看：* 現場也有一維條碼嗎？吵雜 / 戴手套時，需不需要「嗶聲」提示更明顯？
- **現況：** 「相符」是比對 QR 內含的部門 + 地點與清單是否一致。
  - *想想看：* 你們實際的 QR 內容真的有含部門和地點嗎？**這點要跟開發單位確認清楚。**

### 👥 協作 / 規模

- **現況：** 單機單檔，沒有多人同盤一批再合併的機制。
  - *想想看：* 大規模盤點時，需不需要多人分工、最後把結果合起來？
- **現況：** 盤到一半換手機 / 重開，靠寫回的 CSV 續盤，沒有明確的「暫存 / 續盤」流程。
  - *想想看：* 中斷後再回來繼續，需不需要更明確、更安全的續盤機制？

---

**怎麼用這份清單：** 把上半部當「驗收基準」——確認現有功能符合期待；把下半部當「腦力激盪清單」——每一條有感覺的，就是一條潛在的新需求。兩者整理好，就是要交給開發單位的完整輪廓。

### 技術對照（供開發單位參考）

| 功能區塊 | 對應程式 |
| --- | --- |
| 模式選擇 | `ModeSelectActivity.java` |
| 全盤清單 / 篩選 / 進度 | `MainActivity.java`、`ui/AssetAdapter.java` |
| 全盤掃描 / 盤盈新增 / 歷程 | `ScanActivity.java` |
| 抽盤逐筆 / 跳轉未盤 | `SamplingActivity.java` |
| 抽盤目標掃描 / 震動 | `SamplingScanActivity.java` |
| 掃描四態判定 | `logic/ScanClassifier.java` |
| 誤觸過濾（編號格式） | `logic/AssetIdFormat.java` |
| CSV Big5 讀寫 | `data/CsvManager.java` |
| 定點寫檔 / 記憶體資料源 | `data/AssetRepository.java` |
| 資料模型（財產欄位 / 狀態） | `model/Asset.java` |

> 備註：`ScanActivity` 內「掃描後修改部門 / 地點並更新」的功能已實作但目前以註解停用（`ScanActivity.java` 內 `editWatcher` 區段），若使用單位需要現場更正資料，接近可用狀態。
