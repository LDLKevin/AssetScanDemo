# POC 流程審視 — 設計決策與待辦

> **日期**：2026-08-19
> **範圍**：重新審視「ERP 匯出 CSV → USB 傳手機 → App 掃描盤點 → USB 傳回 → 上傳 ERP」整套流程，在 POC 規模下的合理性。
> **狀態**：設計樹已收斂，待實作。明日接續。

---

## 1. 背景與規模結論

| 項目 | 結論 |
|---|---|
| 資料規模 | 整庫 6~10 萬筆；多數作業分批。**最壞情況＝財務部角色，單機約 3 萬筆** → 以 3 萬筆為單機設計目標 |
| 離線範圍 | **只有「掃描現場」離線**；匯出／匯入仍在辦公室有線網路的 PC 完成 |
| 傳輸方式 | USB（手機無法連 WiFi），保留 |
| 記憶體 | 3 萬筆純文字 `Asset` 常駐記憶體僅約 10~30MB，**非瓶頸** |
| 查找效能 | 3 萬筆線性比對每次掃描 < 1ms，**非瓶頸 → 不需要加 HashMap 索引** |
| 真正的成本 | **反覆整份寫檔的磁碟 I/O**（見第 3 節） |

## 3. 寫檔策略（待實作）

**現狀問題**：`MainActivity.handleScanResult()` 每成功掃一筆就 `saveCsv()`，而 `CsvManager.write()` 會重寫整份 3 萬筆。成本是**磁碟 I/O + write amplification**，並有「寫到一半被 kill → 整份 3 萬筆全毀」風險（機率低但後果嚴重）。

**改法**：
1. 掃描成功時**只更新記憶體中的 `Asset`**（`checked` / `checkedAt`）與畫面，不寫檔。
2. 只在 **① 使用者按「儲存」 ② `onPause()` ③ `onStop()`** 時寫一次檔。
3. 該次寫檔改用**「寫暫存檔 → rename 原子替換」**，避免中途損毀既有檔案。
4. 加一個「寫入進行中」旗標，寫檔期間跳過重入。

**效果**：消除「每掃重寫全檔」的浪費與損毀風險；殘餘風險僅「掃了還沒觸發存檔就被 kill」，由 `onPause/onStop` 自動存把窗口縮到極小，POC 可接受。

**涉及檔案**：`MainActivity.java`（`handleScanResult`、`saveCsv`、新增 `onPause/onStop`）、`CsvManager.java`（新增原子寫入）。

## 4. 掃描顯示與冷卻（待實作）

**釐清**：5 秒冷卻真正要解的不是「掃太快」或「併發」，而是**「畫面上的掃描結果會被下一次（可能誤觸）掃描刷掉，使用者還沒看完就沒了」**。用「凍結相機 5 秒」解這問題會連合法的下一件也一起卡住，傷吞吐。

**採用方案：連續掃 + 以下三點讓「顯示」本身穩固**
- **(a)** 掃到的字串**不符資產編號格式** → 判為誤觸，**靜默忽略**，不刷新主資訊區。
- **(b)** 掃描結果**停留在畫面，直到下一個「有效且不同」的資產被掃到**，而非自動消失。
- **(c)** 冷卻縮到 **~0.5~1 秒**，只為防手震連拍。

**盤盈分流**（配合 (a) 的格式檢查）：
| 掃到的字串 | 判斷 | 處理 |
|---|---|---|
| 不符編號格式 | 誤觸 | 靜默忽略 |
| 符合格式 且在清單 | 正常盤點 | ✅ 更新 checked |
| 符合格式 但不在清單 | **盤盈** | ⚠️ 給不同提示（不靜默吞；POC 先不記錄） |

**涉及檔案**：`MainActivity.java`（`handleScanResult` 的分流）、掃描頁的冷卻設定。

## 5. 編碼修正（待實作，已實測）

**Bug**：`CsvManager.read()` / `write()` 使用 JVM 預設編碼（Android 上是 UTF-8），但 ERP 報表匯出為 **MS950**。→ 中文財產名稱**一載入就全亂碼**。

**實測結論**（Android 8.0 / API 26＝本專案 `minSdk`，最壞情況）：
- `MS950` / `windows-950` / `x-windows-950` 三個名字 Android 都認得，但**全部 canonical 成基礎 `Big5`**（Android 無真正 CP950 codec）。
- 常見繁中（如 `財產盤點中文測試`）以 Big5 解碼**完全正確**。
- 同一份 bytes 用 UTF-8 解 → 亂碼 `�]���L�I...`，bug 複現。

**改法**：
1. `read()` / `write()` 兩邊**明確指定 `Charset.forName("Big5")`**。
2. **不加 BOM**（Big5 家族無 BOM，加了會害 ERP 再匯入出錯）。
3. ⚠️ **已知邊界**：Android 只有基礎 Big5、無 CP950 擴充區。若某財產名稱含 MS950 專屬擴充字（廠商符號、罕見字），該字在手機上會顯示 `�`。常見名稱不會踩到；真踩到當個案處理（ERP 匯出端先清）。

**涉及檔案**：`CsvManager.java`（`read` 的 `InputStreamReader`、`write` 的 `OutputStreamWriter`）。

## 7. 上線版（POC 之後）分支，本次不做

- **多人多機併發**：多台裝置各自一份 CSV，回 ERP 時以資產編號為 key 合併。
- **Re-import 衝突**：匯出到上傳期間 ERP 資料若異動（報廢／移轉）的處理。
- **盤點欄位擴充**：盤盈清單、位置／保管人不符、資產狀態、照片佐證。
- **儲存改型**：真上線且資料更大時，再評估改 SQLite/Room。
